# 《倒立摆控制：从拉格朗日到 Transformer》课程总纲

> 一门"从第一性原理到数据驱动"的控制课，全程只用一台小车倒立摆。
> 每讲 = 一段视频（8–12 min）+ 一章讲义（LaTeX）+ 一份可运行代码 + 习题。

---

## 0. 课程定位

| 项目 | 说明 |
|---|---|
| 目标学员 | 有微积分/线代基础、写过一点 Python 的工科生、控制方向研究生、想补"非线性+学习控制"的工程师 |
| 前置知识 | 常微分方程、矩阵、拉格朗日力学（会查即可）、Python + NumPy |
| 贯穿案例 | 同一台小车倒立摆：从下垂摆起并稳定（甩起→捕获→稳摆），全程 50 Hz |
| 最终作品 | 4 个控制器 + 1 个 RL 微调策略，同一评测协议下对比；可选实机/半实物 |
| 教学原则 | 每个公式都能落到代码；每个结论都有数字；失败案例同样讲（能力边界） |

**课程主线**：
`建模 → 线性基线（知道边界）→ 反馈线性化（换坐标）→ 能量整定（换目标）→ 滑模（换鲁棒性）→ 切换（缝合）→ 数据（换表示）→ Transformer（换模型类）→ DAgger（修分布）→ PPO（换目标函数）`

## 1. 课程结构：10 讲 + 1 个结课项目

### 第 1 讲　建模：把一台机器写成方程（视频 3:54 ✅）
- **1.1** 为什么是倒立摆：欠驱动 / 非线性 / 不稳定 / 可实验
- **1.2** 坐标约定、符号表、点质量假设
- **1.3** 拉格朗日力学：动能、势能、Rayleigh 耗散、Euler–Lagrange
- **1.4** 两个耦合方程的推导与化简（出现分母 `m_c + m_p sin²θ`）
- **1.5** 能量：用一个标量概括"摆起来"
- **1.6** 平衡点与线性化：`A`、`B`、特征值 `+4.04`、0.25 s 不稳定时间常数
- **1.7** 可控性与欠驱动性：可控 ≠ 能任意指定（相对阶 `cosθ`）
- **1.8** 数值实现：RK4 与一致性自检
- **实验**：开环倒塌曲线、能量守恒验证、线性化预测精度
- **习题**：6 题（含一道"如果摆是均匀杆而非点质量"）

### 第 2 讲　线性基线：LQR 与它的能力边界（视频 3:11 ✅）

- **2.2** Riccati 方程、`Q/R` 的物理含义、增益的直觉
- **2.3** 闭环极点、带宽与力矩饱和
- **2.4** 吸引域：扫描 `(θ₀, θ̇₀)` 画出 basin
- **2.5** 全局失败：27% 成功率、82% 撞墙

- **实验**：basin 扫描、`Q/R` 权衡曲线
- **习题**：5 题

### 第 3 讲　部分反馈线性化：把"力"变成"加速度"（视频 2:15 ✅）

- **3.5** 奇异点：摆杆通道的 `cosθ` 与"失去权限"

### 第 4 讲　能量整定：把"摆起来"变成标量目标（视频 2:24 ✅）

## 4. 每讲的固定结构（"四段式"）

1. **问题**：这讲要解决的工程问题，先给现象（失败/现象/数字）
2. **推导**：最小必要的数学，控制在 3 个公式以内
3. **实现**：10–30 行核心代码，说清工程细节（饱和、归一化、奇异点）
4. **验证**：拿数字说话（成功率、时间、误差、代价）

## 5. 视频制作规范（保证不重不漏）

- 分辨率 1280×720 @30fps，2× 超采样绘制后降采样（廉价抗锯齿）
- **数学**：所有公式用 **KaTeX 渲染成透明 PNG** 再合成（真 LaTeX 语法、Knuth 字体度量）。
  本机没有 TeX 引擎，KaTeX 是等价替代：`\frac`、`\ddot`、`bmatrix`、上下标全部原生支持。
- **中文**：Songti SC（Regular/Bold/Light），预先做"逐字比对 `.notdef`"的字形覆盖检查 → 不会乱码
- **字幕**：**半透明**（alpha 0.72，用 RGBA 图层真合成，无任何底板/蒙版）；**STHeiti Medium** 32 px；
  按像素宽度折行（最多两行）并按墨迹宽度居中；**支持 `$...$` 内联 LaTeX**，
  公式基线与中文严格对齐（基线位置由 KaTeX DOM 实测，逐公式不同：无下标的 1.00、带下标的 0.80、矩阵 0.61）
- **字幕数字**：展示用阿拉伯数字与 LaTeX（`0.25 s`、`E=-2.943 J`、`第 3 行第 2 列`），
  而 TTS 文本单独给"口语版"（`零点二五秒`、`负二点九四焦耳`、`第三杭第二列`）——显示与朗读各用各的
- **配音**：**edge-tts** 的 `zh-CN-XiaoxiaoNeural`（微软神经语音，需联网；离线回退到 `say`）。
  TTS 缓存键 = `sha1(朗读文本|音色|语速)`，**不是镜头序号**——早期版本用 `s{shot}_{cue}.mp3`
  做文件名，导致第 3–10 讲全部命中了第 2 讲的音频，已修复并按哈希隔离。
  每句分"显示文本 / 朗读文本"两份：`$...$` 只进画面，进 TTS 前会被 `_speakable()` 清洗，
  并有断言防止 `$`/反斜杠漏进朗读（曾出现把 `$` 读成"美元"）。
  逐句合成并测长，字幕时间轴由语音时长反推 → 音字幕天然对齐；
  多音字可用 `{"say": "...行...", "tts": "...杭..."}` 单独指定 TTS 文本（字幕仍显示正确写法）
- **配乐**：程序合成的 Am–F–C–G 环境垫（无版权问题），说话时自动 ducking
- **直角坐标图**：一律带箭头坐标轴、轴标题与数字刻度 —— 能量图 `θ [rad]` / `E [J]`（刻度 −π/0/π、0/−2.943，含虚线基准），
  发散图 `t [s]` / `θ [°]`（刻度 0/0.25/0.5/0.75 s、0/5/10°，曲线用真实 1° 释放轨迹，0.5 s 处打点 = 4.79°）
- **曲线**：600 / 500 点采样 + 2× 超采样绘制，无折线感

### 附录 A：Transformer 内部机制全解

## 7. 工具链说明（重要）

这台机器上没有 `brew` / `ffmpeg` / TeX，且 **manim 装不上**：macOS 版 manim 依赖
`pycairo`，而 `pycairo` 在 macOS 没有 wheel，需要系统 `libcairo`（由 brew 提供）。
因此本项目用了两条并行路线：

| 路线 | 画面 | 音频/字幕 | 本机可用 |
|---|---|---|---|
| A（默认） | `video/render.py`：Pillow 逐帧绘制 + PyAV 编码 | `say` TTS + numpy 合成 BGM + 帧内烧字幕 | ✅ 已产出成片 |
| B（manim） | `video/manim/ch01_scene.py` | `mux_voiceover.py` 把同一份旁白/字幕贴上去 | ❌ 需 manim 环境 |

两条路线的画面语言、旁白、字幕完全一致（同一份 `SHOTS` 脚本、同一字体 Songti SC）。
在有 manim 的机器上执行：

```bash
pip install manim
cd video/manim && manim -qh ch01_scene.py Ch01 -o ch01_silent.mp4
python3 ../mux_voiceover.py ch01_silent.mp4 ../narration_ch01.json
```

**LaTeX 同样无法本地编译**（无 TeX 引擎）。讲义是标准 `xelatex` 工程，需要 `ctex` 宏包：

```bash
cd latex && xelatex main.tex && xelatex main.tex
```

## 8. 公式渲染（KaTeX 本地化）

## 9. 一个曾经藏得很深的排版 bug

`Canvas.text()` 在 2× 超采样画布上绘制时**没有把字号乘以 `ss`**，导致所有文字实际只有设定值的
一半大，而公式走的是另一条（已缩放的）路径 —— 于是整片看起来"公式太大、文字太小"。
修复后统一以"设计像素"为单位：`size=26` 就是屏幕上 26 px。
（这类问题只能靠"同一屏内公式与文字的字号比例"来发现，值得在其它章节复用这套检查。）

## 10. 字形体检（tofu 排查）

KaTeX 或系统字体遇到没有字形的字符时会画成"方框"（tofu）。为此加了两道自动检查：
